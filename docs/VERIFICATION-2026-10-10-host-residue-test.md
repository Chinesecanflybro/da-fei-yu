# 记事：2026-10-10 宿主残留受控实验

> 目的：验证"从 U 盘运行便携版时，是否会在宿主（本机）留下可持久数据"
> 方式：**受控实验**（改注册表 + 运行程序），全程可回滚
> 前置授权：用户明确同意
> 状态标记：`当前已知`（有实测证据）/ `待核验`

---

## 一、实验设计

| 步骤 | 动作 |
|---|---|
| 0 | `reg export "HKCU\...\Run"` 导出备份 → `run-backup.reg`（4,850 B） |
| 1 | 记录宿主相关目录与注册表的基线 |
| 2 | 删除既有的自启项 `DeepSeekDesktopPet`（它指向桌面版，非便携版） |
| 3 | 从 U 盘启动 `启动-大肥鱼-Portable.cmd`，观察 50 秒 |
| 4 | 检查：注册表是否被重写、宿主目录是否出现新写入 |
| 5 | **第二轮（对照）**：先停止宿主的 opencode 进程，再启动便携版，观察 135 秒 |
| 6 | 收尾：关闭程序、清理本次产生的 U 盘临时目录、**用备份还原注册表** |

---

## 二、实验结果

### ✅ 结果 1：本次运行**没有**写自启项

- 启动前 `HKCU\...\Run` 中 `DeepSeekDesktopPet` 已被删除（已验证不存在）。
- 从 U 盘运行 50 秒后复查：**该值未被重新创建**。
- 第二轮运行 135 秒后复查：**仍未被创建**。

> 结论：**从 U 盘运行时，程序未在宿主注册表写入自启项**（`当前已知`）。
> 注意：实验时 U 盘 `data\config.json` 中 `autostart.enabled = true`，
> 在自启已开启的前提下仍未写注册表 —— 这一点比预期更好。

### ✅ 结果 2：本次运行**没有**在宿主用户目录产生新数据

- 12:24 之后被写入的宿主文件中，**无任何**桌宠 / opencode 相关条目
  （命中的全是 OneDrive、微信、抖音、TokenBroker、Office 等无关程序的正常活动）。
- 既有的两个旧目录时间戳**未变化**：
  - `%LOCALAPPDATA%\DesktopPet` → 2026-09-28（旧安装遗留）
  - `%LOCALAPPDATA%\大肥鱼` → 2026-09-29（旧安装遗留）
- OpenCode 的宿主数据目录（本机用户目录下 `.local\share\opencode`）中，
  `opencode.db` 的时间戳为 **11:17:13**，早于本次实验（12:24），**未被本次运行写入**。

### ✅ 结果 3：启动器的 TEMP 重定向**真实生效**

两次启动均在 U 盘生成 PyInstaller 解包目录：

```
H:\大肥鱼-Portable\temp\_MEI000030d02\   (12:24:34 起)
H:\大肥鱼-Portable\temp\_MEI00006a6c2\   (12:28:59 起)
```

内含 `PyQt6\Qt6\bin\Qt6WebEngineCore.dll`（203 MB）、`QtWebEngineProcess.exe`、
`avcodec-61.dll` 等 —— 即**整个 Qt/WebEngine 运行时的解包都留在 U 盘**，
没有落到宿主的 `%TEMP%`。

> 这是"便携"设计最实在的一条收益：临时解包不污染宿主。

### ⚠️ 结果 4：便携版**不会**自动安装/启动自带的 OpenCode

- 第二轮实验中，**先停止**了宿主上运行中的 opencode（`AppData\Roaming\npm\...\opencode.exe`，
  11:17 启动的那个），确认 `127.0.0.1:4096` 端口已释放。
- 随后从 U 盘启动便携版，等待 **135 秒**。
- 结果：**没有**任何 `opencode.exe` 进程出现，**4096 端口始终未监听**。
- U 盘上**始终没有**解包出来的 `opencode.exe`（只有 `opencode-windows-x64.zip` 压缩包本体，
  62,127,126 B，保持原样）。

> 结论：`opencode.autoStart` / `autoInstall` 为 true，但**未触发**。
> 合理推断：OpenCode 的安装/启动是**按需**的（用户点「呼叫 Agent！」时），
> 而非开机即启动。**这一点需在真实点击 Agent 后再验证**（见待核验）。

### ℹ️ 结果 5：上一轮看到的"宿主 opencode 在跑"不是便携版拉起的

第一轮实验时曾观察到 `opencode.exe` 从 `AppData\Roaming\npm` 运行、监听 4096。
但其启动时间（11:17:13）**早于**实验启动时间（12:24:30），
且第二轮（停掉它之后）便携版并没有重新拉起它 —— 说明那是**用户自己的会话**，
不是便携版的行为。

## 六、方法学备注

- 本次为**单机、单次**实验，样本有限；"未发现残留"**不等于**"不存在残留"。
- 宿主的文件夹时间戳只在目录直接子项变化时更新，理论上存在"深度子项写入而父目录时间戳不变"的情形；
  因此结论以"实验窗口内被写入的文件全量清单"为主证据，而非只看目录时间戳。
- 实验前宿主已存在两个旧安装遗留目录（2026-09-28 / 09-29），说明**历史版本的桌宠确实在宿主写过数据**；
  便携版的表现与它们不同，但这不能反推历史版本的行为。
